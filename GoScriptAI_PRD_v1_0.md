# GoScriptAI — PRD v1.0

**Продукт:** GoScriptAI — агентски систем за резултатски ориентирани реел-сценарија со човечки чекпоинти
**Компанија:** GoDigital / GoCode
**Датум:** 05.09.2026
**Статус:** Нацрт за одобрување (Фаза 0 + Фаза 1)
**Јазична конвенција:** UI на македонска кирилица, код и коментари на англиски. Сценарија на македонски или албански според клиентот.
**Однос со GoFactory:** самостоен систем, иста архитектурна филозофија и стек, посебна база, посебен deploy, без заеднички код освен по договор на Tech Lead.

---

## 1. Визија

GoScriptAI е внатрешен систем кој за секој клиент гради **„Мозок на клиентот“** (кој е клиентот, што продава, кому му продава, што прави конкуренцијата, што работи во платените реклами) и врз тој мозок му помага на сценаристот да произведува сетови сценарија кои имаат аватар купец, суштина и мерливи резултати — со задолжителни човечки чекпоинти на секоја клучна одлука.

Принцип: **АИ ја носи меморијата и механиката, сценаристот ја носи одлуката.** Сценаристот знае сè за клиентот во секој момент, но чита само делта, а не сè одново.

Втор принцип: **Системот учи од резултати.** Секое сценарио е поврзано со реклама во Meta Ads Manager; резултатот се враќа во системот и го менува следното сценарио.

## 2. Проблем

- 6.000+ реелови за 2 години; сценаристите пишуваат со Claude.ai без доволен контекст → генерички сценарија без аватар купец и без идеја; резултатите од платените реклами паѓаат.
- Знаењето за клиентот живее во главата на сценаристот и во расфрлани документи; секој сет почнува од нула контекст.
- Нема повратна врска: сценариото не знае дали претходното донело резултат.
- Нема евиденција кој аватар, актер, локација и тип на реел е користен, ниту што работело.
- Двајца сценаристи (Александар и Стефан) пишуваат ~20 сета месечно секој, истовремено на повеќе клиенти; секое сценарио бара многу читање и рачна доработка.

## 3. Цели и метрики на успех

| Метрика | Сега | Цел (3 месеци по Фаза 1) |
|---|---|---|
| Време од бриф до одобрен сет | ~2 часа | < 30 мин |
| Сценарија одобрени без рачна доработка | ретко | ≥ 60% |
| Сценарија со експлицитен аватар, актер и локација | ~0% | 100% (системски задолжително) |
| Сценарија во база поврзани со ad резултат | 0% | 100% за нови; ≥ 80% за увезени |
| Hook rate и cost per result на реелови од системот наспроти рачни (ист клиент, ист месец) | — | мерливо подобрување (Фаза 2 извештај) |
| Логирани агентски сесии и трошок по сет | 0% | 100% |
| Аватари непокриени 3+ сета по ред | непознато | 0 без свесна одлука на сценаристот |

## 4. Опфат по фази

### Фаза 0 — Податоци (2 недели, паралелно со Спринт 1)
- Увоз на постоечки сценарија за реелови кои се или биле во платени реклами, по клиент (сценаристите ги собираат; системот дава bulk import преку docx/markdown/paste).
- Секое увезено сценарио добива код; кодот е еднаков со името на рекламата во Ads Manager.
- Рачно пополнување на Client Brain за 3 пилот клиенти (Алекс Дизајн + 2 други).
- Цел: системот не почнува празен.

### Фаза 1 — MVP (4–5 недели развој)
- Клиенти: креирање, intake (веб, документи, слики, текст-бриф), јазик (мк/сq), договор (реелови/графики месечно).
- **Client Brain агенти:** Клиент-анализа (со прашања кон операторот), Аватари; рачен внес на Продукти, Актери, Локации, Конкуренти, Тренд-референци (линк + транскрипт/текст), Речник.
- **Сет flow:** Бриф → Креативен директор (концепт-карти) → чекпоинт → Писатели паралелно → Критичар → чекпоинт → одобрување/ревизија → експорт во стандарден документ.
- База на сценарија по клиент со верзии, тип, аватар, актер, локација, статус.
- Dashboard: клиенти, Client Brain, сетови, Inbox „Те чека тебе“, „Што е ново“.
- Cost tracking по клиент/сет/агент; нотификации (email + Telegram).
- Повеќе сета паралелно по сценарист и меѓу сценаристи.

### Фаза 2 — Јамка на учење (следен PRD)
- Meta Marketing API sync (дневен): реклами → мапирање на сценарија по име → метрики по објектив.
- Ads-перформанс агент + Инсајти агент (неделни инсајти по клиент и глобално по индустрија).
- Few-shot по резултат (најуспешни сценарија на клиентот како пример за Писателот).
- Meta Ad Library за конкуренти (кои реклами ги пуштаат сега).
- Аватар статистика (% застапеност, резултат по аватар).
- Web search за конкуренција (сајтови, ценовници, рецензии) со човечка потврда за нови ентитети.

### Фаза 3 — Стратег и медиуми
- Стратег/Планер агент (Fable 5.1): стратегија за социјални медиуми + детален планер за реелови и графики според договорот.
- Whisper транскрипција на качени видеа (конкуренција/тренд) + Тренд-аналитичар агент.
- Извештаи за клиенти; долгорочна аналитика по индустрија.

## 5. Корисници и улоги

| Улога | Пристап |
|---|---|
| Scriptwriter (сценарист/режисер) | Своите и туѓи клиенти: гради Client Brain, отвора сетови, одобрува чекпоинти, доработува сценарија, експортира |
| Admin (Operator) | Сè + Поставки, темплејти, буџети, модел-рутирање, увоз, интеграции |
| Viewer | Read-only преглед (менаџмент, дизајнери) |

Клиентот нема пристап и не дава фидбек преку системот (надвор од опфат).

## 6. Технички стек

- **Backend:** Node.js 22 + TypeScript, Fastify
- **Frontend:** React + Vite + Tailwind (SPA), македонска кирилица, mobile-first за чекпоинти
- **База:** PostgreSQL 16 + Prisma ORM (посебна инстанца од GoFactory); pgvector за семантичко пребарување на сценарија и референци
- **Job queue:** BullMQ + Redis — сите агентски run-ови се job-ови, никогаш синхрони со HTTP
- **АИ:** `@anthropic-ai/claude-agent-sdk`; автентикација преку Claude Max претплата (Claude Code CLI login на серверот); **fallback на Anthropic API клуч** ако Max падне или лимитира (автоматски switch со нотификација). Модел-рутирање по агент, уредливо од Поставки.
- **Meta:** Marketing API преку постоечкиот long-lived token (Фаза 2); Ad Library API (Фаза 2)
- **Транскрипција:** Whisper (self-hosted или API) — Фаза 3
- **Документи:** генерирање docx (стандарден темплејт за сценарија) + markdown
- **Хостинг:** Hetzner VPS, Nginx, Docker Compose; посебен сервер или посебни контејнери од GoFactory
- **Нотификации:** Amazon SES + Telegram Bot API
- **Клучна NFR:** сценаристот никогаш не чека на екран за агент — сè оди преку queue со live статус (SSE) и Inbox.

## 7. Агенти — дефиниции

| Агент | Слој | Модел (default) | Алатки | Влез | Излез |
|---|---|---|---|---|---|
| Client Analyst | Brain | Fable 5.1 (fallback Opus) | WebFetch, WebSearch, Read | Веб сајт, документи, слики, текст-бриф | Прашања кон операторот; ClientProfile.md (индустрија, продукти, УСП, тон, онлајн присуство, досегашни кампањи, отворени прашања) |
| Avatar Builder | Brain | Fable 5.1 | Read | Одобрен ClientProfile + продукти | 4–8 Avatar записи: демографија, ситуација, болка, желба, зошто купува, приговори, како зборува, кои продукти му одговараат |
| Competitor Analyst (Ф2) | Brain | Sonnet | WebSearch, WebFetch, Ad Library | Рачно внесени + откриени конкуренти | CompetitorProfile: што рекламира, формати, понуди, слабости; предлог нови конкуренти (чека потврда) |
| Trend Analyst (Ф3) | Brain | Sonnet | Whisper, Read | Линк/видео/транскрипт | TrendReference анализа: структура, hook, зошто работи, како се адаптира за клиентот |
| Ads Performance (Ф2) | Brain | Haiku (парсирање) | Meta Marketing API | Реклами и метрики | AdCreative + AdMetrics записи; мапирање по код; листа немапирани (чека потврда) |
| Insight Distiller (Ф2) | Brain | Fable 5.1 | Read | Сценарија + метрики + аватари | Insight записи по клиент и по индустрија („testimonial со сопственик 2x hook rate…“), важност, доказ |
| Creative Director | Set | Fable 5.1 | Read | Бриф + Client Brain + инсајти + „не го прави ова“ | N×2 концепт-карти |
| Writer (×N паралелно) | Set | Fable 5.1 (fallback Opus) | Read | Одобрен концепт + Brain + примери + речник | Цело сценарио во стандарден формат |
| Critic | Set | Opus | Read | Сценарио + рубрика + речник + актер/локација | CriticReport: оценка по критериум, конкретни поправки; auto-revision барање |
| Strategist (Ф3) | Brain | Fable 5.1 (задолжително) | Read | Brain + договор (реелови/графики месечно) | Стратегија + месечен планер за реелови и графики |
| Reporter | — | Haiku | — | Настани од базата | Резимеа за нотификации и „Што е ново“ |

**Правила за сите агенти (исти како GoFactory):**
- Фиксен system prompt како Template во базата (уредлив од Поставки, со верзии).
- Секој run има max буџет во USD и max траење → `BUDGET_HOLD`.
- Целиот транскрипт се снима како Message записи.
- Prompt caching за Client Brain документите (се повторуваат во секој сет).
- Ниту еден агент не запишува нов ентитет (конкурент, профил, актер, аватар) во база без човечка потврда — предлогот стои во `PENDING_CONFIRMATION`.
- Секој агент што пишува текст за клиентот добива **јазик на клиентот** и **речник** како задолжителен влез.

## 8. Слој A — Client Brain

### 8.1 Onboarding state machine на клиент

```
DRAFT → INTAKE (веб, фајлови, бриф, јазик, договор)
→ ANALYST_RUNNING → ANALYST_QUESTIONS* → ANALYST_REVIEW*
→ AVATARS_RUNNING → AVATARS_REVIEW*
→ MANUAL_SETUP* (продукти, актери, локации, конкуренти, референци, речник)
→ ACTIVE
```

`*` = човечки чекпоинт. `MANUAL_SETUP` не блокира — клиентот може да стане `ACTIVE` со минимум еден актер; сè друго се дополнува.

### 8.2 Ажурирање
- `ACTIVE` клиент има копче „Ажурирај анализа“ (нови документи/бриф → Client Analyst во иста сесија, предлага diff на ClientProfile → чекпоинт).
- Аватарите се ревидираат месечно или на барање; секој аватар има историја на верзии.
- Секоја промена во Brain создава запис во **„Што е ново“** за тој клиент со датум — сценаристот го гледа при следниот бриф.

### 8.3 Ентитети кои сценаристот ги одржува рачно
- **Продукти/Понуди:** име, категорија, цена/рати, УСП, сезоналност, активна промоција (со датум од–до).
- **Актери:** име, улога (сопственик/вработен/ангажиран актер/GoDigital талент), јазици, стил (енергичен, смирен, комичен…), што може/не може (хумор да/не, долги реплики, физичка комедија), забрани, референтни сценарија.
- **Локации:** име, опис, што се гледа, што може да се искористи во нарација, ограничувања, слики.
- **Конкуренти:** име, линкови (сајт, IG, FB, TikTok), зошто е конкурент, „ова НЕ го правиме“ забелешки, статус (потврден/непотврден).
- **Тренд-референци:** линк, платформа, транскрипт (вметнат или од Whisper во Ф3), анализа, флаг `INSPIRATION` или `DO_NOT_COPY`, за кој клиент/индустрија.
- **Речник:** термини по јазик — како клиентот ги вика продуктите, дозволени/забранети зборови, тон, дијалектни зборови на актерот, забранети генерички фрази.

## 9. Слој B — Сет flow

### 9.1 State machine на сет

```
DRAFT → BRIEF_SUBMITTED → CONCEPTS_GENERATING → CONCEPTS_REVIEW*
→ SCRIPTS_WRITING → CRITIC_RUNNING → (AUTO_REVISION ≤ 2 круга)
→ SCRIPTS_REVIEW* (↔ REVISION со коментар, иста сесија)
→ APPROVED → EXPORTED
→ [Ф2] LINKED_TO_ADS → LEARNED → ARCHIVED
```

Специјални статуси: `PAUSED`, `FAILED` (по 3 retry), `BUDGET_HOLD`.

Два човечки чекпоинта по сет. Сетот е независен job — еден сценарист може да има повеќе сета отворени паралелно на различни клиенти; двајцата сценаристи работат независно. Нема лимит на паралелни сетови освен буџетски.

### 9.2 Бриф екран (влез на сценаристот, 3–5 минути)
1. Клиент (ACTIVE) → системот прикажува „Што е ново“ од последниот сет + аватар покриеност (кој аватар колку сета не е таргетиран).
2. Број на сценарија (1–10) и опционална распределба по тип (или „одлучи ти“).
3. Продукт/понуда во фокус (од листа или слободно).
4. Аватари за таргетирање (чекбокс; предлог од системот според покриеност и инсајти).
5. Актер(и) и локација(и) достапни за ова снимање (чекбокс од базата; нов актер → брз внес).
6. Лични забелешки / што кажал клиентот (слободен текст, може празно).
7. Инспирација: линк, вметнат транскрипт, или (Ф3) качено видео → станува TrendReference; сценаристот означува „преработи го ова за клиентот“ или „ова НЕ“.
8. Ограничувања: што да не се прави, времетраење, посебна порака.

### 9.3 Концепт-карти (излез на Creative Director)
За N барани сценарија се генерираат N×2 карти. Секоја карта:
- Тип: `PRODUCT_OFFER` | `EDUCATIONAL` | `TESTIMONIAL` | `SKETCH`
- Аватар (еден примарен), инсајт зошто застанува
- Hook во една реченица
- Актер + локација
- Дополнителен слој (локација/историски момент/сезона) ако има
- Зошто треба да работи — со референца на Insight или на успешно сценарио (Ф2), или на бриф/аватар (Ф1)
- Проценка: времетраење, комплексност на снимање

Сценаристот одбира, брише, коментира, менува аватар/тип, или бара „уште 3 карти во оваа насока“ (иста сесија).

### 9.4 Пишување и Критичар
- По еден Writer job по одобрен концепт, паралелно.
- Writer добива: концепт, ClientProfile, аватар, продукт, актер, локација, речник, 3–5 примери (Ф1: рачно означени „ѕвезда“ сценарија на клиентот; Ф2: по резултат), листа забранети фрази.
- Critic оценува секое сценарио по рубриката (§10) со оценка 1–5 по критериум. Праг: сите критериуми ≥ 3 и вкупно ≥ 80%. Под праг → CriticReport оди назад кај Writer во иста сесија (max 2 круга); потоа сценариото се прикажува со флаг „не помина критика“ и наодите.
- Сценаристот гледа: сценарио, оценка на Критичарот, наоди, и копчиња Одобри / Доработи рачно (инлајн едитор, ја чува верзијата) / Врати со коментар.

### 9.5 Експорт
- Одобрениот сет се генерира како еден docx (и markdown) во стандардниот формат (§11), со наслов „{Клиент} {Месец} Сценарија“, код на секое сценарио, листа актери и локации по сценарио.
- Секое сценарио добива код: `{CLIENT_CODE}-{YYMM}-{NN}` (пр. `ALEKS-2609-03`). **Овој код е името на рекламата во Ads Manager** — единствено правило за мапирање.

## 10. Рубрика на Критичарот

| Критериум | Што проверува |
|---|---|
| Аватар | Јасно се гледа кому му се зборува во првите 3 секунди; болка/желба на аватарот е присутна |
| Hook | Прв кадар ≤ 3 сек, прекинува скролање, конкретен (број, ситуација, контраст), не почнува со име на фирма |
| Суштина | Има една јасна идеја/понуда/поука; не е листа генералности |
| Изводливост за актерот | Реплики соодветни на стилот, јазикот и ограничувањата на актерот; без физички неизводливи барања |
| Локација | Ако е зададена, се користи смислено, не само како позадина |
| Структура | Hook–Body–CTA јасно одвоени; кадри нумерирани; режија присутна |
| CTA | Конкретна акција поврзана со објективот на кампањата (порака, посета, сајт) |
| Анти-генеричност | Нема фрази од листата на забранети; нема „квалитет, доверба, професионализам“ без доказ |
| Јазик | Чист македонски/албански според клиентот; без србизми/бугаризми/буквални англицизми; речникот е почитуван |
| Времетраење | Изговорен текст се вклопува во целното времетраење (~2.5 збор/сек) |
| Точност | Цени, имиња на продукти, рати и промоции се совпаѓаат со базата на продукти |

## 11. Стандарден формат на сценарио (темплејт)

Избран од документот „Алекс Дизајн Август Сценарија“ — структурата на *Сценарио 1 — Ваучер ИУТЕ*, дополнета со опционална табела за производи/цени од *Сценарио 3*. Сите генерирани и увезени сценарија се нормализираат во овој формат.

```
СЦЕНАРИО {NN} — {Наслов} ({Тип} · {Аватар} · {Актер} · {Локација} · ~{сек}s)
Код: {CLIENT_CODE}-{YYMM}-{NN}

КАДАР 1 — ХООК
{Режија во една–две реченици: каде е актерот, што држи, како гледа.}
{Актер}: „{реплика}“

КАДАР 2 — БОДИ
{Режија}
{Актер}: „{реплика}“
(Монтажа: {текст на екран, графика, инсерти} — само ако има)

КАДАР N — БОДИ / набројување
{Режија}
| # | Производ (се изговара) | Стара цена (екран) | Нова цена (екран) |   ← само кога има набројување
{Актер}: „{ритам на реплики}“

КАДАР Z — ЦТА
{Режија: лого, кадри од салон/продукт}

```

Правила: секој кадар има улога (ХООК/БОДИ/ЦТА); режијата е одвоена од репликата; репликата секогаш носи име на актер; забелешките за монтажа се во одделен ред со префикс „Монтажа:“; бројки што се појавуваат на екран се и во табела.

## 12. Dashboard — екрани

1. **Клиенти** — листа со статус на Brain, јазик, договор (реелови/графики месечно), сетови овој месец, аватар покриеност, „чека тебе“ индикатор.
2. **Client Brain** — табови: Профил (со верзии и diff), Аватари, Продукти, Актери, Локации, Конкуренти, Референци, Речник, Инсајти (Ф2), Што е ново.
3. **Сетови** — листа по клиент/сценарист/статус; нов сет = Бриф екран.
4. **Сет детали** — временска лента; Концепт-карти (одбирање); Сценарија (со оценка на Критичарот, инлајн едитор, верзии); Транскрипти во живо (SSE); Трошок; Експорт.
5. **База на сценарија** — пребарување по клиент, тип, аватар, актер, статус, резултат (Ф2); семантичко пребарување („сценарија со хумор за рати“); означување „ѕвезда“ примери.
6. **Inbox „Те чека тебе“** — сите чекпоинти од сите клиенти и сетови; одобри/коментирај директно; филтер по сценарист.
7. **Увоз** — bulk import на стари сценарија (docx/paste), доделување код и клиент, нормализација во формат, преглед пред запис.
8. **Резултати (Ф2)** — по клиент: сценарија со метрики по објектив, топ/дно, аватар и тип извештаи; немапирани реклами за потврда.
9. **Извештаи** — по сет, по клиент, месечно (трошок наспроти Max кредит; сетови по сценарист).
10. **Поставки** — темплејти на агенти (system prompts, верзии), рубрика на Критичарот, листа забранети фрази (глобална + по јазик), формат на сценарио, модел-рутирање и fallback, буџети, Meta token, нотификации.

## 13. Meta Ads интеграција (Фаза 2 — дефинирано сега за да се подготви моделот)

- Дневен sync преку Marketing API за сите ad accounts достапни со long-lived token; чита ads со video creative.
- **Мапирање:** име на рекламата == код на сценарио → автоматско. Без совпаѓање → `PENDING_MAPPING` во Inbox, сценаристот избира сценарио или „не е наше“.
- **Метрики по објектив:**
  - `THRUPLAY`: ThruPlays, cost per ThruPlay
  - `MESSAGES`: messaging conversations started, cost per conversation
  - `ADD_TO_CART` / `PURCHASE`: број и cost per result
  - Универзални за креативата: impressions, spend, hook rate (3-sec views / impressions), hold rate (avg watch time / duration), CTR
- **Оценка „работи / не работи“:** cost per result и hook rate се споредуваат со медијаната на **истиот клиент во последните 90 дена**; сценариото добива перцентил. Не се споредуваат клиенти меѓу себе (различни индустрии и буџети), освен во инсајти по индустрија.
- Резултатите се запишуваат на Script записот и стануваат влез за Insight Distiller и за few-shot изборот на Writer.

## 14. Јазици

- `Client.language` ∈ {MK, SQ, BOTH}. За `BOTH` сетот може да бара сценарија на еден или двата јазика; двојазично сценарио е две верзии со ист код и суфикс `-MK` / `-SQ`.
- Актерот има `languages`; Creative Director не додава актер на концепт на јазик кој не го зборува.
- Речник и листа забранети фрази постојат по јазик.
- Критичарот има јазичен критериум по јазик на сценариото.

## 16. Cost tracking и буџети

- Секој AgentRun запишува трошок од SDK output во CostEntry (по клиент и по сет).
- Буџет по клиент месечно (default $50, уредлив) и по сет (default $8); 80% → предупредување; 100% → `BUDGET_HOLD`.
- Проценка: сет од 5 сценарија ≈ 10 концепт-карти + 5 Writer + 5 Critic + ревизии ≈ $3–6 со Fable/Opus. При 40 сета месечно ≈ $150–250 + Brain ажурирања. Месечен екран наспроти Max кредитот и API fallback трошок.

## 17. Error handling и отпорност

- Retry со exponential backoff (max 3); rate limit → пауза со тајмер.
- Max недостапен → автоматски fallback на API клуч за тековниот run + нотификација до Admin; враќање на Max при следниот run.
- Секој run е resumable преку session_id; чекпоинт по фаза во базата.
- Паралелни Writer job-ови се независни — пад на еден не го руши сетот; сетот чека или продолжува со останатите по одлука на сценаристот.
- Транзициите се транскациски; ниту еден сет не останува во недефинирана состојба.

## 18. Безбедност

- Dashboard зад автентикација (JWT, bcrypt), улоги, опционален IP allowlist.
- Meta token и API клучеви само во .env; никогаш во промптови, логови или git.
- Агентите имаат read-only пристап до uploads и Brain документи; пишуваат само во својот сет workspace.
- Клиентски податоци (цени, стратегии, аватари) не излегуваат од системот освен во експортот.
- Дневен backup на Postgres + uploads.

## 19. Нотификации

Канали: email (SES) + Telegram bot, по корисник. Настани: концепти спремни; сценарија спремни; сценарио не поминало критика по 2 круга; Brain предлог чека потврда; немапирана реклама (Ф2); буџет 80%/100%; грешка/FAILED. Секоја нотификација носи директен линк.

## 22. План за имплементација — Фаза 0 + Фаза 1 (4 спринта × ~1 недела)

**Спринт 1 — Скелет:** Repo, Docker Compose (Node, Postgres+pgvector, Redis, Nginx), Prisma модел + миграции, автентикација и улоги, CRUD за Клиент и сите Brain ентитети (продукти, актери, локации, конкуренти, референци, речник), intake форма со upload, BullMQ основа, state machine за клиент и сет. **Паралелно Фаза 0:** екран за увоз + нормализација во формат; сценаристите почнуваат да внесуваат сценарија за 3 пилот клиенти.

**Спринт 2 — Client Brain агенти:** Agent SDK интеграција + Max auth + API fallback, Client Analyst (research → прашања → профил), Q&A екран, Avatar Builder, Approval тек со верзии и diff, „Што е ново“, транскрипти во живо (SSE), cost tracking.

**Спринт 3 — Сет flow:** Бриф екран, Creative Director → концепт-карти → одбирање, паралелни Writer job-ови, Critic со рубрика и auto-revision, Сет детали екран со инлајн едитор и верзии, ревизија во иста сесија, експорт docx/markdown во стандарден формат, база на сценарија со пребарување.

**Спринт 4 — Операција:** Inbox „Те чека тебе“, нотификации, буџети и BUDGET_HOLD, Поставки (темплејти, рубрика, забранети фрази, модел-рутирање), извештаи, mobile UI, работилница за system prompts со сценаристите, тест со 3 реални сета по сценарист.

**Definition of Done за Фаза 1:** Александар и Стефан секој завршуваат по 3 реални сета низ системот (бриф → концепти → сценарија → критика → одобрување → docx кон клиент) без Claude.ai и без copy-paste; секое сценарио има аватар, актер, локација и код; сите транскрипти, трошоци и одобрувања се во dashboard-от; трите пилот клиенти имаат целосен Client Brain и увезени стари сценарија.
