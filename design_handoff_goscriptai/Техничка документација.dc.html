GoScriptAI — техничка документација

По екран: рута, состојби, податоци, API повици, задолжени агенти, транзиции, крајни случаи и критериуми за прифаќање. Референци: PRD v1.0 (§7 агенти, §9 сет flow, §15 модел) и Design Brief v1.0 (§7 екрани, §8 компоненти).

Заедничка основа

FrontendReact + Vite + Tailwind (SPA), јазик на UI: македонска кирилица; код и имена на компоненти на англиски.
BackendNode 22 + TypeScript + Fastify; Postgres 16 + Prisma; pgvector за семантичко пребарување.
АгентиBullMQ job-ови; никогаш синхроно со HTTP. Живи статуси преку SSE /api/streams/set/:id.
АвтентикацијаJWT; улоги SCRIPTWRITER / ADMIN / VIEWER. Viewer нема пристап до чекпоинт мутации.
Дизајн токениpaper #F5F6F4 · sheet #FFF · ink #1B1F24 · ink-2 #5A6270 · rule #D9DDE3 · signal #E4572E · ok #2F7D4F · hold #B7791F · fail #9B2C2C. signal само на човечка одлука.
ТипографијаIBM Plex Sans 400/500/600 за UI; IBM Plex Mono за сценарија и кодови. Скала 13/14/16/20/28.
Заеднички компонентиStatusBadge, CheckpointBar, ScriptView/ScriptEditor, ConceptCard, PersonCard, PlaceCard, AvatarCard, CriticScore, WhatsNewList, DiffView, AgentStatusLine, TranscriptViewer, ContextSheet, EmptyState, ErrorState, Toast, ConfirmDialog, DataTable.

7.1 Чека тебе (Inbox)

Рута/ (стартна)
APIGET /api/inbox?mine=bool → групи: CONCEPTS_REVIEW, SCRIPTS_REVIEW, PENDING_CONFIRMATION, PENDING_MAPPING, BUDGET. Извор: ScriptSet.status, Script.status, ентитети во PENDING_CONFIRMATION, CostEntry агрегат.
Ред{clientId, clientName, logoUrl, setCode, kind, waitingSince, writerUserId, deepLink}. Сортирање по waitingSince опаѓајќи.
ЖивоSSE /api/streams/inbox; на нова ставка бројачот пулсира еднаш (prefers-reduced-motion го исклучува).
Состојбипразно (со број активни сетови), со ставки, филтрирано празно, грешка при вчитување.
Крајни случаиСтавка решена од другиот сценарист додека гледаш → редот се отстранува со toast. Клиент без лого → монограм.
ПрифаќањеКлик на ред отвора точниот екран на одлуката, не преглед. Ниту една ставка не бара пребарување за да се разбере.

7.2 Клиенти

Рута / API/clients · GET /api/clients?sort=waiting
ПресметкиbrainCompleteness (недостасува актер / локација / речник по јазик), setsThisMonth наспроти reelsPerMonth, avatarCoverage[avatarId][lastNSets] (bool), waitingCount.
Состојбинема клиенти (покана „Нов клиент“), клиент во onboarding (без сетови), архивиран клиент.
ПрифаќањеПокриеноста се чита без легенда; долго име на клиент не крши редот.

7.3 Клиент — Onboarding

Рута / API/clients/new · POST /api/clients, POST /api/clients/:id/intake (multipart upload), POST /api/clients/:id/analyst/run, POST /api/clients/:id/analyst/answers, POST /api/clients/:id/profile/:v/approve
State machineDRAFT → INTAKE → ANALYST_RUNNING → ANALYST_QUESTIONS* → ANALYST_REVIEW* → AVATARS_RUNNING → AVATARS_REVIEW* → MANUAL_SETUP* → ACTIVE (* = човечки чекпоинт). ACTIVE е возможен со минимум еден актер.
АгентиClient Analyst (WebFetch, WebSearch, Read) → прашања + ClientProfile; Avatar Builder → 4–8 Avatar во PENDING_CONFIRMATION.
Состојбианализа во тек (статус линија, без спинер), прашања (текст / избор / „не знам“, со прогрес), профил на преглед (Одобри / Врати со коментар), одобрено, BUDGET_HOLD, FAILED по 3 retry.

7.4 Клиент — Преглед

Рута / API/clients/:id · GET /api/clients/:id/overview → {changeLog[], avatarCoverage[], sets[], budget}
МоделBrainChange{kind, summary, createdAt} го полни „Што е ново“; се создава при секоја промена во мозокот и при враќање резултат.
Прифаќање„Што е ново“ е првото што се чита; „Нов сет“ е единственото доминантно копче.

7.5 Клиент — Мозок

Рута/clients/:id/brain/:tab, tab ∈ profile · avatars · products · actors · locations · competitors · references · glossary · insights
APICRUD по ентитет: /api/clients/:id/{products|actors|locations|competitors|references|glossary}; GET /api/clients/:id/profile?version= + GET …/diff?from=&to=; POST /api/entities/:id/confirm|reject за PENDING_CONFIRMATION.
КомпонентиПрофил: документ 68 знаци + DiffView. Аватари: AvatarCard со линија на покриеност и верзии. Продукти: DataTable со инлајн уредување (optimistic update, rollback при 4xx). Актери/Локации: PersonCard/PlaceCard. Конкуренти: потврдени + одделна секција предлози.
ИнвариантаНиту еден агент не запишува ентитет надвор од PENDING_CONFIRMATION. Речникот и јазикот на клиентот се задолжителен влез во секој агент што пишува текст.
Крајни случаиПродукт со промоција во минато → неактивен, но останува за историски сценарија. Аватар RETIRED не се предлага во бриф. Клиент BOTH јазик → речник и забранети фрази по јазик, одделно.

7.6 Нов сет — Бриф

Рута / API/sets/new?client= · POST /api/sets со brief JSON (PRD §9.2) → 201 {setId}, потоа enqueue CreativeDirectorJob.
Влезни полиња{clientId, requested:1..10, typeMix[], productIds[], offerText, avatarIds[], actorIds[], locationIds[], notes, inspiration:{url|transcript, flag:INSPIRATION|DO_NOT_COPY}, constraints, targetSec}
ВалидацијаЗадолжително: клиент ACTIVE, ≥1 актер, ≥1 аватар. Актер без јазикот на сетот се отфрла со објаснување. Инспирацијата се создава како TrendReference пред пуштањето.
ПредлозиДва аватари се предизбрани по правилото: најдолго непокриени, потоа по тежина на инсајт (Ф2).
ТранзицијаDRAFT → BRIEF_SUBMITTED → CONCEPTS_GENERATING. UI не блокира; корисникот е ослободен веднаш.

7.7 Сет — Концепти (чекпоинт 1)

Рута / API/sets/:id/concepts · GET /api/sets/:id/concepts; PATCH /api/concepts/:id {decision, comment, avatarId, type}; POST /api/sets/:id/concepts/more {referenceConceptId}; POST /api/sets/:id/write.
АгентCreative Director: N×2 карти од бриф + Client Brain + инсајти + „ова НЕ“. „Уште 3“ работи во истата сесија (sessionId од AgentRun).
КартаConcept.card = {hook, insight, why, layers[], estimateSec, complexity} + type, avatarId, actorId, locationId, decision ∈ PENDING|SELECTED|REJECTED.
ТранзицијаCONCEPTS_REVIEW → SCRIPTS_WRITING: по еден Writer job на секој SELECTED концепт, паралелно. Отфрлените остануваат како негативен сигнал за следниот бриф.
Состојбисе генерираат (прогрес линија), спремни за избор, избрани (read-only резиме за стари сетови), 0 избрани (копчето „Пиши“ е неактивно), BUDGET_HOLD.

7.8 Сет — Сценарија (чекпоинт 2, херој екран)

Рута / API/sets/:id/scripts/:scriptId · GET /api/scripts/:id; POST /api/scripts/:id/approve; PUT /api/scripts/:id/content (рачна доработка, создава нова version); POST /api/scripts/:id/revise {comment}.
ФорматScript.content = {frames:[{n, role:ХООК|БОДИ|ЦТА, sub?, direction, lines:[{actor,text}], editing?, table?{head[],rows[][]}}]}. Нормализиран за генерирани и увезени сценарија (PRD §11).
ScriptViewMono 16px / line-height 1.7 / max 68 знаци; улога и број на кадар во левата маргина; режија курзив ink-2; име на актер 600; „Монтажа:“ издвоен ред; табела за бројки на екран. ScriptEditor е истиот изглед со contentEditable по поле — зачувувањето чита назад по data-e клуч и создава нова верзија.
КритикаcriticReport = {scores:{criterion:1..5}, findings:[{frame, text}], total}. Праг: сите ≥ 3 и вкупно ≥ 80%. Под праг → назад кај Writer, max 2 круга, потоа CRITIC_FAILED со наоди. „Скокни до кадар“ = anchor #frame-N + краткотрајно означување.
ТранзицииSCRIPTS_WRITING → CRITIC_RUNNING → (AUTO_REVISION ≤2) → SCRIPTS_REVIEW ↔ REVISION → APPROVED. Секое одобрување пишува Approval{checkpoint:'SCRIPTS', decision, comment, userId}.
Состојбисе пишува · во критика · се доработува · чека тебе · не помина критика · одобрено · експортирано. Паралелен пад на еден Writer не го руши сетот.
РаспоредЛиста 200–230px · сценарио 1fr (min 460px) · ContextSheet 280–320px, собирлив. Под ~1000px колоните се прекршуваат вертикално; на мобилен контекстот е долен sheet и акциите се лепливи (48px).
ПрифаќањеСценаристот чита сценариото како на хартија и одобрува со едно копче; наодите водат до точниот кадар; ниту една акција не бара објаснување.

7.9 Сет — Експорт

Рута / API/sets/:id/export · POST /api/sets/:id/export → {docxUrl, mdUrl}, статус EXPORTED, ScriptSet.exportPath.
Код{CLIENT_CODE}-{YYMM}-{NN}, unique; идентичен со името на рекламата во Ads Manager — единствено правило за мапирање (Ф2). „Копирај код“ користи clipboard API со fallback.
ДокументНаслов „{Клиент} {Месец} Сценарија“; страница по сценарио во форматот од PRD §11; список актери и локации по сценарио.
УсловДостапен само кога сите сценарија во сетот се APPROVED; инаку блокирана состојба со бројач одобрени.

7.10 Сет — Транскрипти и Трошок

APIGET /api/sets/:id/runs, GET /api/runs/:id/messages, SSE /api/streams/run/:id; GET /api/sets/:id/cost.
МоделAgentRun{agentKind, model, sessionId, costUsd, status} + Message{role, content}; CostEntry по клиент и сет.
БуџетDefault $8 по сет, $50 по клиент месечно; 80% → предупредување и нотификација, 100% → BUDGET_HOLD и чекпоинт.
UIГуст, монохромен TranscriptViewer; tool call-ови собирливи; имињата на моделите се дозволени само тука и во Поставки.

7.11 База на сценарија

Рута / API/scripts · GET /api/scripts?q=&client=&type=&avatar=&actor=&status=&lang=&star=. Едно поле: точно совпаѓање по код/наслов, плус pgvector семантичко пребарување по markdown embedding — без посебен „AI search“ UI.
АкцијаPOST /api/scripts/:id/star — ѕвезда примерите се few-shot влез за Writer додека нема метрики (PRD §9.4).
ПрегледИстиот ScriptView, read-only.

7.12 Увоз

APIPOST /api/import/parse (docx / paste / повеќе фајлови) → нормализирани кадри + предупредувања; POST /api/import/commit со {clientId, code, type, avatarId, actorIds, adDate}.
UIПарсираниот резултат во ScriptView до оригиналот; предупредувања како „не најдов ЦТА“; состојби: парсирање, парсирано со предупредувања, зачувано.
Крајни случаиДупликат код → предлог следен слободен NN. Сценарио без улоги на кадри → рачно доделување пред запис.

7.13 Резултати (Фаза 2)

ИзворДневен Meta Marketing API sync; AdCreative + AdMetrics; мапирање по име на реклама == код. Без совпаѓање → PENDING_MAPPING во Inbox.
МетрикиПо објектив (THRUPLAY, MESSAGES, ADD_TO_CART, PURCHASE) плус impressions, spend, hook rate, hold rate, CTR; перцентил наспроти медијаната на истиот клиент за 90 дена.
UI правилоСамо хоризонтални ленти и една временска линија. Без пити и без графикони заради графикони.

7.14 Извештаи и Поставки

ИзвештаиПо сет, по клиент, месечно; трошок наспроти Max кредит; сетови по сценарист; PDF експорт.
Поставки (Admin)Template по агент со верзии (текст едитор + историја), рубрика на Критичарот, забранети фрази по јазик, формат на сценарио, модел-рутирање и fallback, буџети, Meta token (маскиран), нотификации по корисник, корисници и улоги.
FallbackMax претплата недостапна → автоматски switch на API клуч за тековниот run + нотификација; трошокот се означува одделно.
Квалитетно дно (важи за секој екран)

Респонзивно до 360px; видлив keyboard focus; контраст AA вклучувајќи ink-2 на sheet; prefers-reduced-motion целосно почитуван; секоја икона со текст или aria-label на македонски; кирилицата тестирана со Ѓ Ќ Ѕ Џ Љ Њ и Ç Ë во сите тежини; долги имиња на производи и реплики не кршат распоред; сите транзиции на состојба се транскациски — ниту еден сет не останува недефиниран.
